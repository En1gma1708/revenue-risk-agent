Add checker/reflection agent, retroactive review pass, and frontend polish

Backend -- checker/reflection agent (a real 4th agentic pattern):
- backend/pydantic_agents.py: add CheckerVerdict, _make_checker, _needs_checker_review,
  _run_checker_review -- a genuine second agent that reviews a specialist's ALREADY-COMPLETED
  decision (single-shot, not a live re-run of the specialist's loop), triggered only on
  cases worth the cost (any HARD_STOP hit, final tier APPROVE_FIRST, or router severity high).
  On a flag, bounded to exactly one specialist retry (never re-checked again) or escalation
  to a human. Also adds a real router->specialist handoff tool (hand_off_to_specialist,
  async to avoid a run_sync-inside-a-tool deadlock) with retry-then-escalate if the router
  never completes a valid handoff, replacing a prior silent default-to-payment-specialist
  fallback.
- backend/metrics.py: add compute_checker_metrics (cases reviewed/flagged/retried/escalated,
  review rate, flag rate) -- same "live query over real log data, never hand-picked"
  discipline as every other metric in this project.
- backend/app.py: wire compute_checker_metrics into /metrics as a new "checker" field.
- backend/run_checker_retroactive.py (new): retroactively runs the checker against the
  already-completed real 95-case batch, spending quota only on the genuinely new work
  (checker calls + any triggered retries), not re-running already-successful router/specialist
  decisions. Idempotent -- safe to re-run, skips already-reviewed cases.
- backend/tests/test_pydantic_agents.py: 12 new tests for the checker (all mocked, zero
  quota) -- all 5 trigger-rule branches, both log-entry shapes, and all 3 end-to-end outcomes.
- backend/tests/test_checker_metrics.py (new): 3 tests for compute_checker_metrics.
- NOVELTY.md: Reflection row rewritten from "does not fit" to a real, load-bearing pattern,
  with the live-verification evidence (forced escalate/retry scenarios, and the real
  retroactive run's 87/90 reviewed, 10 flagged, 0 escalated result). Net-result line updated:
  3 patterns now genuinely load-bearing (tool use, orchestrator-worker, Reflection).

Real batch-scale result (data/revenue_risk_multiagent.db, gitignored, not in this commit):
95/95 clean cases unaffected throughout; checker reviewed 87 of 90 triggered real cases,
flagged 10 (11.5%), all resolved via bounded retry, 0 needed human escalation. Also surfaced
a real, previously-unknown finding: 59% of the batch's APPROVE_FIRST escalations were the
model self-escalating (via escalate_to_human) rather than the deterministic guardrail engine
actually firing -- documented in DEVLOG.md (gitignored).
